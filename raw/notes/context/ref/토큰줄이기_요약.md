# 토큰줄이기 발표 스크립트 요점정리 — 발표자: 메이커 에반

## 핵심 명제: 컨텍스트가 왕
- 같은 리액트 질문: 1214 토큰 vs 294 토큰, 답 내용은 거의 같음. 차이는 모델·요금제가 아니라 `무엇을 넣고 뺐느냐`
- 50점 도구가 환경 잡으면 95점. ChatGPT·Gemini에도 공통 적용

## 전제 1: 책상이 넓어 ≠ 다 채워도 된다
- 컨텍스트 윈도우 = 작업 책상. 3년간 250배 확대
- 스탠포드 연구: 긴 내용 한 번에 → 처음·마지막만 기억, 가운데는 30%+ 성능 하락 `Lost in the Middle`
- 발표자 경험: 100줄 매뉴얼 → 목차+챕터 분할만으로 자원 40~60% 감소
- 자동 요약 지점 = `성능의 절벽`. 원본 사라지고 요약만 남음
- 결론: `신선한 컨텍스트 > 쌓아놓은 컨텍스트`

## 전제 2: 돈 세는 곳 3개
1. **뱉는 쪽(출력):** 자서전식 장문 답변. 코드 한 줄 찾는데 5분 설명 반복. 돈+시간 이중 손실
2. **넣는 쪽(입력):** 매뉴얼·대화기록·통파일. 통째로 밀어넣기가 잘게 찾아쓰기보다 최대 82배 비쌈. 티 안나게 조용히 비쌈
3. **안 보이는 비용:** 책상 지저분 → 세션 조기 사망 → 새 대화에서 다시 설명하는 시간

절약 팁:
- 브라우저/MCP는 필요할 때 창 그대로 사용. 찌꺼기 안 쌓이고 100~200ms, ~20배 빠름
- MCP 연결(전화기)은 필요한 것만. 안 쓸 도구 설명서가 매번 올라와 책상 차지
- 모델 섞기: Opus 플랜=계획, Sonnet=코딩. 비싼 머리 판단에만
- 아끼지 말 곳: Codex로 최종 교차검토. 토큰 들지만 실수 1개 잡으면 이득

## 방법 1: 뱉는 걸 줄이기 — 케이브맨(Caveman, 원시인)
- 스킬 = 신입 인턴 안내문 1장. 내용 3줄: `군더기 빼라. 짧게 말해라. 기술용어는 정확하게`
- 효과: 평균 -65%, 최대 -87%. 1214 → 294 토큰, 920 절약, 매 질문 반복
- 예: 리액트 렌더링 장문 → `새 객체가 생긴다. 메모로 감싸라.` 2줄
- 신뢰 근거: 이미 짧게 답하는 모드와 비교해도 더 짧음. 비교가 정직
- 부가 효과: 짧게 시키면 정확도 오히려 상승, 최대 +26점. 길게 말하면 자기 말에 흔들림(시험지 고쳐쓰기)
- 단계: Lite(인사말만 제거) / 기본 / Ultra(전보체)
- 딸림 기능: 커밋메시지 50자·why 위주, 한줄 코드리뷰, CLAUDE.md 리라이트 평균 -46% — 매 세션 읽히니 누적 절약 큼

## 방법 2: 통째로 밀어넣지 않기 — RAG 접음
- RAG = 문서 자르기→숫자 변환→유사 조각 검색. 자르는 순간 맥락 상실이 문제. 예: `마케팅 비용 15% 증가` 한 줄만으론 회사·분기 모름
- Claude Code는 RAG 안 씀. 사람처럼 `파일 검색 → 10줄만 읽기 → 필요하면 10줄 더`
- 비유: RAG=라이다(정밀·무거움·고장 전파) vs 직접탐색=카메라(단순·모델 좋아질수록 좋아짐)
- 제대로 하려면: 하이브리드검색(의미+키워드)+리랭크+GraphRAG 필요. 구축·유지비 큼
- 실용 3안:
  1. 양 적으면 그냥 통째로. 자름 없음=맥락 유지, 단 비싸니 소량만
  2. Contextual Retrieval(Anthropic): 조각 앞에 `어디쯤인지` 설명 붙이기. 실패율 -67%
  3. 요약으로 검색·원문으로 전달: 요약본 인덱싱 → 실제 전달은 원본 단락. 도서관 목록-본문 방식. 발표자 최애

> 단순 RAG 퇴물. `미리 다 넣기 → 필요할 때 찾아오기`

## 방법 3: 한 책상에 안 쌓기 — 서브에이전트(분신술)
- 핵심: 분신은 빈 새 책상에서 시작. 메인 서류 1장도 못 가져감. 장점이자 제약
- 최악 패턴: CEO·디자인·테스팅 역할별 조직도. 테스팅은 메인 맥락 필요한데 못 받음 → 남의 집 청소
- 원칙: 완전히 독립적인 일에만. 자료조사·예제수집·후보비교
- 쓸 때: 지시는 평소보다 길게. 무엇을·왜·범위까지. 대화 못 봤다고 가정
- 효과: 메인 안 더러워짐. 30분 사망 대화 → 2시간 유지
- 발표자 조합: 계획정리 → 분신 분할 → 분신 2단계 검토(지시대로?+품질?) + 타사 모델(Codex가 Claude 놓친 것 잡음)
- 보고: `다 했습니다` 금지. 무엇을 발견·어떻게 고침·왜 그렇게 판단까지
- 물리 분리: worktree로 폴더 복사해 3개 병렬, 안 엉킴

> 분신은 인원 증원이 아니라 `깨끗한 책상 증설`

## 저녁 30분 5가지 세팅
1. **CLAUDE.md 만들기:** 프로젝트 투어시켜 자동 생성. 필수 3요소: 뭘 만드는지 / 무슨 도구 / 검증 체크리스트(자동 검수대). AI코딩 실패 90%는 검수대 부재
2. **50줄로 쪼개기:** 파일당 50줄 내외, 목차+필요 챕터만 펼치기. 전체룰+프로젝트룰 2층(지점이 우선). 맨 위 절대룰 섹션. 같은 실수 2번이면 AI에게 매뉴얼 고치라 시킴
3. **강제 펼치기(훅):** 앞 훅=지시 전 관련 매뉴얼 찔러주기, 뒤 훅=끝난 후 오류·보안 빠짐 되묻기. 판단 조건 4개: 키워드·의도·위치·파일내용
4. **기억을 파일에:** 착수 전 계획서·맥락노트·할일 3종. 승인 순간 멈추고 `문서 저장→새 대화→읽고 이어해`. 한 번에 다 시키지 말고 1~2개씩 확인
5. **자주 비우기:** 요약 기다리지 말고 일 끝나면 지우기. 노트도 관련만. 도구 한꺼번에 설치 금지. 별점 조작·프롬프트 인젝션 주의

## 효과 측정 4개 숫자(주간)
1. 컨텍스트 사용량% — 하단 플러그인 상시 표시
2. 아낀 양 — 케이브맨 스탯(토큰·금액)
3. 대화 수명 — 새로 열고 흐려질 때까지. 2시간이면 성공
4. 재설명 횟수 — 작대기 집계, 3회+면 구멍. 실수 유출 0 목표. 세팅 2일 투자 → 10배 이상 회수. 가성비 1위는 매뉴얼 쪼개기
